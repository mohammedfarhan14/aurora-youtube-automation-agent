# ADR-0006: Separate live topic discovery from factual research

- **Status:** Accepted architectural direction; implementation pending.
- **Date:** 2026-11-12
- **Context:** PR #104 adds deterministic local-first topic diversification from a channel editorial profile and recent research topics. The current live research adapter searches English Wikipedia only. Neither capability provides live trend discovery, broad independent source retrieval, source reliability ranking, or evidence reconciliation.
- **Decision:** Introduce provider-neutral ports for trend discovery, source search, exact-document retrieval, source policy, deterministic topic ranking and evidence reconciliation. Treat trends as discovery signals only; factual assertions require retrieved source evidence. Preserve existing ResearchDocument and evidence persistence contracts through backward-compatible evolution.
- **Rationale:** Separating popularity signals from factual evidence prevents a trending claim from being mistaken for a verified claim. Separate adapters allow open-source/local-first operation, provider replacement, explicit terms/rate-limit review, deterministic tests and no implicit paid fallback. Ranking remains explainable and does not require an LLM.
- **Initial adapter candidates:** approved Google Trends interface where available, YouTube Data API search metadata, Hacker News API, curated RSS/Atom publisher feeds, optional policy-reviewed Reddit API access, Wikimedia/Wikidata reference retrieval, and optional operator-hosted SearXNG. No candidate is enabled merely by appearing in this list.
- **Source assessment:** retain source class, publisher, publication/retrieval times, content hash, stable excerpt locator, provenance and explainable reliability dimensions. Detect syndication and near-duplicates; represent conflicting evidence explicitly.
- **Security:** approved source registry, SSRF-resistant retrieval, strict egress controls, bounded parsing, prompt-injection isolation, tenant/channel scoping, credential encryption and deterministic mock-only CI.
- **Consequences:** Additional adapters, observation/evidence metadata, evaluation fixtures and operational controls are required. Hosted live retrieval cannot be enabled until issue #41 egress controls are verified. Existing mock provider remains the default. Human editorial review and publishing-consent gates remain unchanged.
- **Alternatives rejected:** Treating search-result ranking or social engagement as factual verification; relying on a single search provider; scraping sites that prohibit it; enabling undocumented endpoints or paid fallbacks by default; using an LLM as an opaque topic score or source-trust oracle.
- **Related work:** #41 (network egress), #48 (source/media rights), #49 (Intelligence Layer), PR #104 (topic novelty ranking).
